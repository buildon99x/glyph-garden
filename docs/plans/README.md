# Plans

Plans describe how work will be done.

Use plans for implementation strategy, migrations, investigations, releases, and multi-step quality work.

## Template

```md
# Plan: Title

- Status: Draft | Active | Completed | Abandoned
- Date: YYYY-MM-DD
- Owner: Name or role

## Objective

What outcome should this plan achieve?

## Steps

1. Step with verification.
2. Step with verification.

## Risks

- Risk and mitigation

## Verification

- Command, review, or artifact that proves completion

## References

- Related spec, ADR, playbook, raw material, or source file
```
