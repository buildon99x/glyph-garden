# Release Checklist

Use this checklist when preparing or reviewing a Glyph Garden release.

## Before Reviewing the Release PR

- Confirm the release PR was generated by Release Please.
- Confirm the version bump is reasonable for the included product changes.
- Confirm the PR updates:
  - `CHANGELOG.md`
  - `package.json`
  - `package-lock.json`
  - `.release-please-manifest.json`

## Changelog Review

- Keep only player-facing product changes.
- Keep gameplay, controls, UI clarity, accessibility, and player-visible fixes.
- Remove:
  - coding-agent guidance,
  - GitHub Actions or CI setup,
  - dependency maintenance,
  - internal docs,
  - test-only changes,
  - refactors with no player-visible behavior change.
- Rewrite generated entries so they describe what the player experiences.

## Verification

Run:

```sh
npm run check
npm run build
```

If the release includes UI changes, also run the game locally:

```sh
npm run dev
```

Verify the first screen loads and the core placement loop still works:

1. Select a candidate.
2. Hover an empty plot.
3. Place the glyph.
4. Confirm score, Last Move, and goal progress update.

## After Merge

- Confirm the GitHub release was created.
- Confirm the release notes match the reviewed changelog.
- If a release mistake reveals a repeatable lesson, add it to `.context/kb/lrn/`.
