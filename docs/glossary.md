# Glossary

Shared project language for Glyph Garden.

## Gameplay Terms

| Term | Meaning |
|------|---------|
| Glyph | A placeable tile on the garden board. |
| Candidate | One of the three glyph choices available to place on the current turn. |
| Garden | One stage within a run. A garden has its own board, goals, rules, and turn limit. |
| Run | A full session made of five gardens. |
| Turn | One player placement. A garden usually has 12 turns unless modified by a rune. |
| Chain | The number of reactions caused by a placement. |
| Goal | A per-garden objective the player must complete to continue the run. |
| World Rule | A temporary modifier applied to a garden, such as Rain Garden or Night Garden. |
| Rune | A reward chosen between gardens that modifies future play. |
| Hover Preview | The ghost tile and affected-cell highlight shown before placement. |
| Last Move | The HUD summary of the most recent placement score and reaction chain. |

## Glyph Types

| Glyph | Meaning |
|-------|---------|
| Seed | A growth glyph that can become Bloom when adjacent to Water. |
| Water | A reaction glyph that grows adjacent Seeds into Blooms. |
| Bloom | A scoring glyph that contributes to row harmony bonuses. |
| Stone | An amplifier glyph that strengthens neighboring glyphs. |
| Moth | A mobile or Bloom-sensitive glyph depending on world rules. |
| Prism | A color-copying glyph that reacts with diagonal tiles and row colors. |

## Project Terms

| Term | Meaning |
|------|---------|
| ADR | Architecture Decision Record stored in `.context/kb/adr/`. |
| LRN | Lesson learned stored in `.context/kb/lrn/`. |
| Playbook | Repeatable workflow stored in `.context/kb/playbook/`. |
| Spec | Product or system requirements stored in `docs/specs/`. |
| Plan | Execution strategy stored in `docs/plans/`. |
| Raw Material | Unprocessed source material stored in `docs/raw/`. |
| Product Changelog | Player-facing release notes in `CHANGELOG.md`. |

## Release Terms

| Term | Meaning |
|------|---------|
| Conventional Commit | Commit message format used by Release Please to infer release notes and version bumps. |
| Release Please | Automation that opens release PRs with changelog and version updates. |
| Release PR | Pull request generated by Release Please and reviewed by maintainers before release. |
